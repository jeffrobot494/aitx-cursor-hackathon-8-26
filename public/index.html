The problem

Two ways NPCs already fail

Dialogue trees

Every plot beat is a combinatorial explosion. Someone on the writing team has to remember who was in the room, who talks to whom, and what they are allowed to say.

Naive RAG

Put the world in a vector store and every character can recite the twist. Proximity in embedding space is not a social graph. The hermit knows the plot because the document does.

The product

One endpoint per NPC

A game studio defines its cast. Hearsay decides what each character knows. The studio hits one endpoint and stops maintaining dialogue trees.

POST /v1/npc/:id/chat
{ "message": "what happened on the north road?" }

→
{ "reply": "…",
  "latencyMs": 480,
  "grounding": [
    { "belief", "confidence", "route", "distortion" }
  ]
}

This is what a studio buys.

How it works

Two models. Two jobs.

WhenModelJob
A world event fires Grok 4.6 Who learns it, by what route, how distorted. Twenty to forty seconds. Nobody is waiting.
A player talks to an NPC Fast, non-reasoning Speak using only what the write path already granted. Sub-second.

The social graph is the channel. No tie and no proximity means no knowledge. Grok 4.6 is not summarising the plot — it is deciding the epistemic state of the world.

The test

If Bell knows, the product is broken.

Bell is a hermit with no ties. After the north-road event she still says she wouldn’t know anything about that. A naive RAG system hands her the news because it is in the vector store. Hearsay does not.

Monday morning

What a studio actually does

Define the cast

Name, role, ties, and a hard ceiling of facts they must never know.

Fire world events

Grok 4.6 routes each one. Provenance and distortion are stored, not the author’s truth.

Hit one endpoint

The game talks to /v1/npc/:id/chat. The NPC answers from what they were granted.
